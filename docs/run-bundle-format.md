# Run bundle format, schema 1

The unit `mpt` and Metal-PT write and a future upload website reads. One run = one directory. Everything is plain
text (JSON and CSV, UTF-8). Code: `Sources/MPTCore/Bench/` (`RunInfo.swift`, `RunBundle.swift`, `CSV.swift`, `Privacy.swift`).

## Layout

    ~/Documents/Metal-PT/runs/<yyyyMMdd-HHmmss>-<slug>.mptrun/
        run.json        required
        samples.csv     required, 1 row per second
        frames.csv      optional, 1 row per frame
        summary.html    generated by `mpt record` / `mpt run` when they finish, and again by
                        `mpt summary`; not part of the upload

- `<yyyyMMdd-HHmmss>` is the run start in **UTC**, so the name does not depend on the machine's time zone.
- `<slug>` is the game exe name: lowercased, each run of characters outside `[a-z0-9]` becomes one `-`, leading and
  trailing `-` removed, cut to 40 characters (trailing `-` trimmed after the cut). Empty becomes `game`.
- Collision: if the directory already holds a `run.json`, `-2`, `-3`, ... is appended before `.mptrun`.
- Upload = the zip described in "Upload file" below. The directory name carries no meaning; read `run.json`.

## run.json

Pretty-printed, sorted keys, camelCase. Dates are ISO-8601 (`2026-11-24T14:48:26Z`). `?` = optional, may be absent
or null. A reader must treat any missing optional key as unknown.

| key | type | meaning |
|---|---|---|
| `schema` | int | Format version. 1 now. |
| `appVersion` | string | mpt version that wrote the run. |
| `machine.modelID` | string | Model identifier, e.g. `Mac16,5`. |
| `machine.chip` | string | e.g. `Apple M4 Max`. |
| `machine.gpuCores` | int? | GPU core count when known. |
| `machine.gpuMaxMHz` | int? | Top GPU clock, MHz, from the IORegistry `pmgr` frequency table (the table whose entry count matches IOReport `GPUPH`'s states). Absent when no table fits, and in runs written before 2026-11-24. |
| `machine.gpuClockTableMHz` | [int]? | The GPU frequency table, MHz per GPUPH state P1…P*n* (rounded, OFF left out), from the same `pmgr` table. [?] P*n* ↔ entry *n* is unverified; the limiter analysis uses it to bound its clock rule. Absent when no table fits, and in runs written before it. |
| `machine.memoryGB` | int | Installed RAM, GB, rounded. |
| `machine.osVersion` | string | macOS version, e.g. `26.6`. |
| `machine.osBuild` | string | macOS build, e.g. `25G...`. |
| `game.exe` | string | Executable name (Windows exe for Wine games, from argv[0]); empty if the game process was never identified. |
| `game.title` | string? | Human title. `game.title` (user-editable) names the game and is what runs are grouped by; `game.exe` is the detected recorded app, never edited, used for the folder slug and the Compare 'recorded app' row. |
| `game.storeAppID` | string? | Store id when known. Steam: `steam:<digits>` (the game's `SteamAppId` environment variable, digits only; anything else is left absent). |
| `stack.runtime` | string? | `Protium`, `CrossOver`, `Whisky`, `Kegworks`, `GPTK`, `Wine (unknown)` (a Wine build no named runtime claims), `native`; null when detection failed |
| `stack.runtimeVersion` | string? | Runtime version when its bundle exposes one. |
| `stack.wineArch` | string? | `arm64ec` or `x86_64`. |
| `stack.translator` | string? | x86 translator: `FEX`, `Rosetta`, or absent. |
| `stack.graphics` | [string] | Graphics layers detected, e.g. `DXMT`, `D3DMetal`, `vkd3d`, `KosmicKrisp`. May be empty. |
| `settings.powerMode` | string? | macOS power mode at start: `automatic`, `low`, `high`. |
| `settings.onACAtStart` | bool? | On AC power when the run started. |
| `settings.displayWidth`, `displayHeight` | int? | Main display size at start (`CGDisplayPixelsWide`/`High` of the main display). Absent when unknown. |
| `settings.refreshHz` | number? | Main display refresh rate at start (current display mode). Absent when unknown (0). |
| `graphics.preset` | string? | In-game preset: `low`, `medium`, `high`, `veryHigh`, `ultra`, `custom`. The whole `graphics` object is optional (absent in older runs); unknown strings read as absent. |
| `graphics.width`, `graphics.height` | int? | Render resolution the user set in the game. |
| `graphics.upscaler` | string? | `off`, `metalfx`, `fsr`, `xess`, `dlss`, `other`. |
| `graphics.upscalerMode` | string? | `quality`, `balanced`, `performance`, `ultraPerformance`, `native`; needed unless `upscaler` is `off`. |
| `graphics.frameGeneration` | bool? | Frame generation on. Publishing needs all of preset, size, upscaler (and its mode) and frame generation. |
| `user.label` | string | Free text given with `--label`. Default empty. |
| `user.gameSettings` | string | Free text given with `--settings`: in-game settings. Default empty. |
| `user.notes` | string | Free text given with `--notes`. Default empty. |
| `user.videoURL` | string? | A YouTube link in canonical form `https://www.youtube.com/watch?v=<11-char id>`; anything that does not parse as YouTube is rejected, never stored. |
| `start` | date | Run start (recording start, includes warm-up). |
| `end` | date? | Run end. Absent if the recorder was killed hard. |
| `steadyStartS`, `steadyEndS` | number? | Steady window, seconds since `start` (`elapsed_s`). Warm-up end to run end. Readers use it only when `steadyStartS > 0`, else compute their own. |
| `fpsSource` | string | `log` (per-second counts from the Metal HUD unified-log lines), `stderr` (per-frame, from `mpt run`), or `none`. |
| `warnings` | [string] | Things the recorder noticed (e.g. `game process never identified`, `frame times may include more than one process`). |

## samples.csv

Header row, then one row per second. **Read by header name**, never by position. RFC-4180 quoting. Numbers use `.` as
the decimal separator, no grouping, whatever the machine's locale. **Empty cell = unknown** (not zero).

| column | unit | decimals | meaning |
|---|---|---|---|
| `t` | ISO-8601 UTC, ms | | Sample wall-clock time, e.g. `2026-11-24T14:48:27.012Z`. |
| `elapsed_s` | s | 1 | Seconds since run start. |
| `fps` | frames/s | 1 | Frames in the last second from the Metal HUD of the followed process. Needs the HUD (see below). |
| `fps_pid` | pid | 0 | Process the FPS came from. Not stable across runs. |
| `fps_app` | text | | Exe name of that process (path-scrubbed). |
| `ft_p99_ms` | ms | 2 | 99th-percentile frame interval within that second. Only with per-frame times (`mpt run`). |
| `ft_max_ms` | ms | 2 | Longest frame interval within that second. Only with `mpt run`. |
| `gpu_w` | W | 2 | GPU power from IOReport `GPU Energy`. **May under-read**: measured about 1.2 W while SMC rails rose about 12 W under a GPU load (hardware-baseline E6). Treat as a lower bound. |
| `cpu_p_util_pct` | % | 1 | P-core utilisation (IOReport residency; busy = 1 - IDLE/DOWN share). |
| `cpu_e_util_pct` | % | 1 | E-core utilisation. |
| `cpu_core_max_pct` | % | 1 | Busiest single core. |
| `gpu_busy_pct` | % | 1 | GPU busy (1 - `OFF` state share). |
| `smc_PSTR_w` | W | 2 | SMC `PSTR`. Measured: system total (equals DC-in on AC). |
| `smc_PDTR_w` | W | 2 | SMC `PDTR`. Measured: DC-in. |
| `smc_PHPC_w` | W | 2 | SMC `PHPC`. SoC rail, rises with CPU and GPU. `[?]` exact meaning. |
| `smc_PHPS_w` | W | 2 | SMC `PHPS`. `[?]` meaning. |
| `smc_PSVR_w` | W | 2 | SMC `PSVR`. `[?]` meaning. |
| `smc_PZC0_w`, `smc_PZC1_w` | W | 2 | SMC `PZC0`/`PZC1`. `[?]` meaning. |
| `smc_PMVC_w` | W | 2 | SMC `PMVC`. `[?]` meaning. |
| `smc_PPMC_w`, `smc_PPSC_w` | W | 2 | SMC `PPMC`/`PPSC`. `[?]` meaning. |
| `temp_max_c` | deg C | 1 | Hottest `PMU tdie*` HID sensor (CPU/SoC die). With no `PMU tdie*` sensor, the hottest of all HID temperature sensors except exactly `PMU tcal`. |
| `temp_battery_c` | deg C | 1 | SMC `TB0T`. |
| `fan0_rpm`, `fan1_rpm` | rpm | 0 | Fan speeds (SMC `F0Ac`, `F1Ac`). Empty if the fan does not exist. |
| `mem_used_gb` | GB | 2 | Memory in use. |
| `battery_pct` | % | 0 | Battery charge. |
| `battery_w` | W | 2 | Battery power, voltage x current; negative while discharging. |
| `on_ac` | 0/1 | | `1` on AC power, `0` on battery. |
| `thermal_state` | text | | macOS thermal pressure (`ProcessInfo.thermalState`): `nominal`, `fair`, `serious`, `critical`. |
| `gpu_mhz` | MHz | 0 | GPU clock: IOReport `GPUPH` residency-weighted mean over the active (non-`OFF`) states, P*n* → entry *n* of the `pmgr` `voltage-states*` table (hardware-baseline 2026-11-24; the P*n* mapping is `[?]`). Empty when the GPU was off the whole second or no table fits this Mac. |
| `mem_pressure` | text | | `kern.memorystatus_vm_pressure_level`: `normal` (1), `warn` (2), `critical` (4); empty if unreadable or another value. |
| `swap_used_gb` | GB | 2 | Swap in use (`vm.swapusage` used), GiB. |
| `compressed_gb` | GB | 2 | Memory held by the compressor (`host_statistics64` compressor pages × page size), GiB. |
| `pageouts_per_s` | 1/s | 0 | Pages written out per second (`host_statistics64` pageouts, difference between ticks). Empty on the first tick. |

Columns are append-only: the five above were added 2026-11-24 after `thermal_state`; older runs lack them and readers
must treat a missing column as unknown.

The `smc_*` columns are SMC keys as measured on one machine (MacBook Pro M4 Max); their meanings are tagged `[?]`
unless hardware-baseline says "measured", and key availability differs between Mac models. Do not compare them across
models without checking. Details: `docs/hardware-baseline.md` (E6).

FPS comes from Apple's Metal HUD log lines, so it exists only for Metal processes launched with the HUD variables set
(`mpt hud on`, or `mpt run`). Without it `fps`, `fps_pid`, `fps_app` are empty and `fpsSource` is `none`.

## frames.csv

Optional; only written by `mpt run` (per-frame times arrive on the game's stderr). Header `t_ms,interval_ms,present_delay_ms`,
one row per frame, all numbers with 2 decimals.

| column | unit | meaning |
|---|---|---|
| `t_ms` | ms | Frame time since run start. Approximate: placed backwards from the arrival of each batch (about 1 s) by the cumulative intervals. |
| `interval_ms` | ms | Time since the previous frame. |
| `present_delay_ms` | ms | Present delay of the frame, as the HUD reports it. |

1 % and 0.1 % lows are computed from this file; without it they are not available. They use the frames of the steady
window: a samples row at `elapsed_s` t covers the second (t − 1, t], so steady rows first…last take frames with
`t_ms / 1000` in [first − 1, last).

Stderr frames carry no process id, so several Metal processes under the launched command can interleave here. While
recording, `mpt run` checks each second after the warm-up (the lows use only those frames). It adds the warning
`frame times may include more than one process` when, for 3 consecutive such seconds, either the stderr frame count
is more than 15 % above the followed process's log FPS (only when that process is in the launched command's
process group), or more than one process in the launched command's process
group gains frames in the log while stderr frames arrive. Processes outside that group, for example other apps with the
HUD on, are ignored. With that warning the summary and compare
show the lows as "—" ("frame times mixed").

## Privacy

Guarantee: no user name, home path, hostname or serial number in any bundle file. Applied at write time (`Privacy`):

- Home paths `/Users/<name>` (any case) become `~`; Wine paths `X:\Users\<name>` become `X:\Users\~`, and Unix paths
  into a Wine prefix `…/drive_c/users/<name>` become `…/drive_c/users/~`. Applies to every string in `run.json`.
- Host names (this machine's host name and computer name, with `.local` removed, first DNS label, and the
  `LocalHostName` form) become `<host>`, whole-word and case-insensitive. Names under 4 characters and `localhost`,
  `mac`, `macbook` are not scrubbed. Applies to free-text fields: `game.*`, `stack.*`, `settings.powerMode`, `user.*`,
  `warnings`, and the text columns `fps_app`, `thermal_state` and `mem_pressure`.
- The serial number is not collected.
- Not scrubbed: anything a user types into `--label`, `--notes` or `--settings` that is not a home path or this machine's host name
  (for example a real name). A website should treat `user.*` as untrusted free text.

## Upload file (`<run>.mptrun.zip`)

What the app's Submit sheet ("Export file…") and `mpt export RUN` write, and what the website will accept. Written to
`~/Documents/Metal-PT/exports/` (the data root's `exports`; `mpt export --out DIR`) as `<run folder name>.zip`, so
`20261124-120000-hzd-exe.mptrun.zip`; when the name is taken, `-2`, `-3`, … go before `.mptrun.zip`. The name is
rebuilt from the run, never taken from the folder (which a user may have renamed to anything): `yyyyMMdd-HHmmss` of
`run.json` `start` in UTC, then the slug of the privacy-scrubbed `game.exe`, as new run folders are named.

The zip holds one folder with that name, so unzipping it gives a run folder that `mpt` and the app read:

    20261124-120000-hzd-exe.mptrun/
      frames.csv      only if the run has one; re-written from its numbers: the three columns above (by header
                      name, 2 decimals), rows with a missing or non-numeric value dropped, other columns dropped
      manifest.json
      summary.json    headline numbers (see "summary.json" below); listed in the manifest
      run.json        the run's run.json, re-scrubbed; user.notes is "" unless the user opted in
      samples.csv     the run's samples.csv with every text cell scrubbed again (`fps_app`, `thermal_state`, `mem_pressure`, and any
                      cell in any column that is not a number); numbers and column order unchanged

Nothing else from the run folder is included: no `summary.html` (the website renders its own), no dot-files, no
other files. The zip is made with `ditto -c -k --norsrc --noextattr --noqtn --noacl --keepParent`, so it has no
`__MACOSX/` or `._*` (AppleDouble) entries.

`manifest.json` is written last and does not list itself:

```json
{
  "app" : "0.2.0",
  "files" : [
    { "bytes" : 196712, "path" : "frames.csv", "sha256" : "<64 lowercase hex>" },
    { "bytes" : 1180, "path" : "run.json", "sha256" : "…" },
    { "bytes" : 21933, "path" : "samples.csv", "sha256" : "…" }
  ],
  "format" : "metal-pt-run",
  "includesNotes" : false,
  "schema" : 1
}
```

| Key | Meaning |
|---|---|
| `format` | Always `metal-pt-run`. |
| `schema` | The manifest's format, 1. (`run.json` carries its own `schema`.) |
| `files` | Every other file in the folder, sorted by `path`: size in bytes and SHA-256 of its exact contents. |
| `app` | Version of the Metal-PT (or `mpt`) that exported it (`MetalPTVersion.current`); the version that recorded it is `run.json` `appVersion`. |
| `includesNotes` | The user ticked "Also send my notes"; when false `run.json` has `user.notes` empty. |

Privacy: the run folder's scrubbing (above) applies, and `run.json` and the text cells of `samples.csv` go
through it again on export (a bundle may come from an older or other writer). The label and
game settings are always included (they are the point of a submission); notes only when opted in.

Size: when the files listed in the manifest total more than 25 MB (25 × 1024 × 1024 bytes, uncompressed), export is
refused ("This run is too large to submit"), to keep within a single Cloudflare Worker request body.

## summary.json

Written into the zip (and listed in `manifest.json` with size and hash) and sent as its own upload part. Sorted keys,
absent numbers are `null`. It is a convenience the website re-checks from `samples.csv`, never trusted on its own.

| key | meaning |
|---|---|
| `summaryVersion` | 1. |
| `medianFPS`, `p1LowFPS` | Median FPS and 1 % low over the steady rows (`p1LowFPS` needs `frames.csv`). |
| `fpsPerWatt` | `medianFPS` divided by mean power of `powerSource`; null without power. |
| `meanSystemW` | Mean `smc_PSTR_w` over steady rows; null unless `powerSource` is `system`. |
| `steadyStartS`, `steadyEndS` | The run's recorded steady window, or null. |
| `limiter` | `{ primary, verdict }` from the limiter analysis; `primary` is `memory`, `frameCap`, `gpuThermal`, `gpu`, `cpuOneThread`, `cpu`, `unclear` or null. |
| `powerSource` | `system` (`smc_PSTR_w`), `gpuOnly` (`gpu_w`, a lower bound) or `none`. |
| `publisherVersion` | Optional (left out when absent): the version of the app that made the file (publishing or exporting it). metal-pt.com checks its minimum app version on this, else on run.json `appVersion`. |

Row selection is `RunSummary`: with `steadyStartS > 0` the rows from it to `steadyEndS`; otherwise the most common
`fps_app`, the first 10 s dropped, rows above 2 x the median FPS dropped. Golden examples: `Tests/Fixtures/site/`.

## Publishing

The app uploads the zip plus byte-identical `run.json`, `samples.csv` and `summary.json` as multipart parts, signed with
a per-Mac P-256 key. The request contract, headers and signed message are in
`docs/superpowers/specs/2026-11-25-metal-pt-website-design.md` section 4.B. `mpt payload RUN --out DIR` writes the four
parts; `scripts/make-site-fixtures.sh` builds the website's test fixtures from them.

A website should check `format`, every listed file's size and hash, reject unknown files, and treat all text as
untrusted.

## Compatibility rules

- `samples.csv` columns are **append-only**: existing columns are never renamed, reordered, removed or re-united.
  New columns go at the end.
- Readers map columns **by header name**. A column missing from a file is unknown; an **unknown column is ignored**.
  Rows may be shorter than the header; extra cells are ignored.
- A reader must accept a bundle with no `frames.csv`, empty cells anywhere, and missing optional `run.json` keys.
- New optional keys may be added to `run.json` in schema 1; unknown keys are ignored.
- `schema` is bumped only for a change old readers cannot handle (a meaning change, a removed or renamed field, a
  changed unit). A reader that sees `schema` greater than it knows should still try, and warn that the data may be misread.
  `mpt` itself shows a warning, not an error.
